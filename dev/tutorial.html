An example workflow ​

This page walks through a small analysis from start to finish: a project with its own functions, a pipeline, a first build, a look at the graph, a code change, new data that breaks the build, and the tools for finding out why. Every output on this page was produced by running the code shown, in order, when the documentation was built.

1. Create a project ​

A Targets project is an ordinary Julia project: its functions live in a package, and _targets.jl at its root says which targets to build from them. Create one with Pkg (press ] at the REPL), and add the packages the analysis uses, Targets, a Makie backend for plotting the pipeline and Revise for editing code without restarting Julia:

julia
pkg> generate MyAnalysis
pkg> activate MyAnalysis
pkg> add CSV DataFrames Statistics
pkg> add https://github.com/arnold-c/Targets.jl
pkg> add CairoMakie Revise

By the end of this section the project looks like this:

MyAnalysis/
├── Project.toml          # created by `generate`, lists the packages
├── src/MyAnalysis.jl     # the analysis code, a module
├── data/readings.csv     # the input data
└── _targets.jl           # the pipeline

The code ​

The analysis code is a module in src/MyAnalysis.jl. Keeping functions in a package, rather than in _targets.jl, means they are compiled once, can be tested and reused, and can define types whose values Targets can store and load again. Replace the file that generate created with:

julia
module MyAnalysis

using CSV, DataFrames, Statistics

export load_readings, clean_readings, station_summary, warming_trend

"Read the raw temperature readings."
load_readings(path) = CSV.read(path, DataFrame)

"Drop readings outside a plausible range: sensor errors."
clean_readings(readings) = filter(:temperature => t -> -50 <= t <= 60, readings)

"Mean, minimum and maximum temperature of each station."
station_summary(readings) = combine(
    groupby(readings, :station),
    :temperature => mean => :mean,
    :temperature => minimum => :min,
    :temperature => maximum => :max,
)

"How fast each station warms, in degrees per day."
warming_trend(readings) = combine(groupby(readings, :station)) do g
    (; per_day = slope(g.day, g.temperature))
end

slope(x, y) = sum((x .- mean(x)) .* (y .- mean(y))) / sum((x .- mean(x)) .^ 2)

end

The pipeline ​

_targets.jl loads the code and declares the targets. Each @target names a result and the expression that computes it; the targets an expression mentions are its dependencies. raw_file is a file target: its value is the path, and Targets watches the file's contents, so editing the data rebuilds everything that reads it.

julia
using Targets
using MyAnalysis

@pipeline begin
    @target raw_file  = "data/readings.csv"  format = :file
    @target readings  = load_readings(raw_file)
    @target cleaned   = clean_readings(readings)
    @target summaries = station_summary(cleaned)
    @target trends    = warming_trend(cleaned)
end

tar_make loads _targets.jl, works out which targets are outdated, and builds them in dependency order. Each target's line says why it was built: missing, because nothing has been stored yet. The results go to the store, _targets/ in the project. (In a terminal, the targets still running are shown in a live footer instead of the ▶ lines.)

3. Look at the pipeline ​

tar_visnetwork draws the pipeline, coloured by status. With CairoMakie it is a static figure; with GLMakie or WGLMakie you can drag targets around, zoom, and hide parts of the graph.

julia
tar_visnetwork()

The square is the file target, and green means up to date. tar_status gives the same information as text, grouped by kind of target:

julia> tar_status()

  raw_file   up to date
Computations (4)

  cleaned    up to date
  summaries  up to date

5 up to date

4. Change the code ​

Report each station's standard deviation too. Edit station_summary in src/MyAnalysis.jl:

diff
     :temperature => maximum => :max,
+    :temperature => std => :sd,
 )

Revise loads the new definition when you press enter at the REPL. Before building, check what the change affects. tar_outdated lists the targets a build would run, with the reason for each:

julia
julia> tar_outdated()

5. New data breaks the build ​

The next day, new readings arrive. Station C's sensor sent nothing, so its temperature is empty:

diff
 C,4,16.3
+A,5,14.1
+B,5,9.6
+C,5,

The data file changed, so every target that depends on it is outdated:

julia
julia> tar_outdated()
5-element Vector{@NamedTuple{name::Symbol, reason::Symbol}}:
 (name = :raw_file, reason = :file_changed)
 (name = :readings, reason = :upstream_outdated)
 (name = :cleaned, reason = :upstream_outdated)
 (name = :summaries, reason = :upstream_outdated)
 (name = :trends, reason = :upstream_outdated)

Build again:

julia
julia> tar_make()
▶ raw_file (file_changed)
✔ raw_file 0.0s (file_changed)
▶ readings (upstream_changed)
✔ readings 0.39s (upstream_changed)
▶ cleaned (upstream_changed)
✖ cleaned: TypeError: non-boolean (Missing) used in boolean context
ERROR: TypeError: non-boolean (Missing) used in boolean context

cleaned failed, so the build stopped and rethrew its error. summaries and trends were not run: they keep their previous values, and are rebuilt once cleaned succeeds.

So the new row for station C has a missing temperature, and the comparison -50 <= t <= 60 cannot decide whether missing is in range. tar_rerun calls the target's current function on the saved arguments, with the same seed, in your session, to reproduce the error; wrap it in Infiltrator.jl's @exfiltrate or Debugger.jl's @enter to step through it:

julia
julia> tar_rerun(:cleaned)
ERROR: TypeError: non-boolean (Missing) used in boolean context

7. Fix it and rebuild ​

Missing readings are not plausible readings either, so clean_readings should drop them:

diff
 "Drop readings outside a plausible range: sensor errors."
-clean_readings(readings) = filter(:temperature => t -> -50 <= t <= 60, readings)
+clean_readings(readings) = filter(:temperature => t -> !ismissing(t) && -50 <= t <= 60, readings)
